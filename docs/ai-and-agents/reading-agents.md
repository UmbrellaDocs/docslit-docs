# How agents read your site

Agents do better with clean Markdown than with scraped HTML. Every `docslit build` writes machine-readable files next to your HTML pages, and sites on DocsLit Cloud add a hosted MCP endpoint. You do not configure any of this.

## Files in the build output

| File | Purpose |
|---|---|
| `llms.txt` | Index of every page: title, description and Markdown URL, grouped by sidebar group. Follows the [llmstxt.org](https://llmstxt.org) format |
| `llms-full.txt` | The full text of every page in one file, with a `# Source:` marker before each page |
| `{slug}.md` | The Markdown source of each page, with includes and compile-time variables expanded |
| `search-index.json` | The index that powers site search, also used by agents |
| `.well-known/agent.json` | Discovery file that lists all of the above |
| `mcp-server.js` | A standalone MCP server over stdio. See [MCP server](mcp-server#the-generated-mcp-serverjs) |
| `robots.txt` | Allows common search and AI crawlers and points at the sitemap |

For a site with `versions`, each version has its own `llms.txt`, `llms-full.txt`, `search-index.json` and Markdown files in a folder named after the version. The root `llms.txt` becomes a version index.

Every page also carries a short agent directive, in the HTML and in the `.md` file. It points to `llms.txt` and to the page's own Markdown URL, following the [Agent-Friendly Documentation Spec](https://agentdocsspec.com/spec/).

### llms.txt

```markdown
# DocsLit

> Documentation for DocsLit - build beautiful docs with Markdown and web components

> Raw Markdown for each page: append `.md` to the page URL, or request the page with `Accept: text/markdown`. Every link below already points at the Markdown.

## Getting started

- [Introduction](https://docs.docslit.com/0.1/getting-started/introduction.md): DocsLit is a documentation framework that combines Markdown with interactive web components.
```

Write a good `description` in each page's frontmatter. It becomes the line after the link. The [lint](../cli-reference/lint) rule `missing-description` checks for it.

### agent.json

`.well-known/agent.json` tells an agent where everything is, so it needs one request to learn the layout:

```json
{
  "name": "DocsLit",
  "description": "Documentation for DocsLit",
  "spec": "https://agentdocsspec.com/spec/",
  "docs": {
    "llms_txt": "https://docs.docslit.com/llms.txt",
    "llms_full_txt": "https://docs.docslit.com/0.1/llms-full.txt",
    "search_index": "https://docs.docslit.com/0.1/search-index.json",
    "markdown_pattern": "https://docs.docslit.com/{version}/{slug}.md"
  },
  "content_negotiation": {
    "accept": "text/markdown",
    "description": "Request any page URL with Accept: text/markdown to receive raw Markdown"
  },
  "pages": [
    {
      "slug": "getting-started/introduction",
      "markdown": "https://docs.docslit.com/0.1/getting-started/introduction.md"
    }
  ],
  "versions": ["0.1"],
  "default_version": "0.1"
}
```

The file lists every page. This example is shortened to one. Set `url` in `docslit.json` so these links are absolute.

## Content negotiation

An agent can request any page URL with `Accept: text/markdown` and receive Markdown instead of HTML:

```bash
curl -H "Accept: text/markdown" https://docs.example.com/getting-started/quickstart
```

A request gets Markdown when its `Accept` header ranks `text/markdown` at least as high as `text/html`, counting quality values. `text/markdown, text/html;q=0.9` gets Markdown, and browsers keep getting HTML.

`docslit dev` does this for you locally. For a static build, `docslit build` writes the pieces each host needs. Cloudflare Pages and Vercel need one extra step, because they read these files only from the project root:

Run `docslit deploy --cloudflare` once after a build to copy it to `functions/` in your project. Later builds refresh that copy, but only when it carries the "generated by DocsLit" marker. The build also writes `_headers` so `.md` files are served as `text/markdown`.

</wc-tab>
<wc-tab label="Vercel">

Run `docslit deploy --vercel` in your project root. It writes `middleware.js`, which serves the page's Markdown, and a `vercel.json` with clean URLs, unless you already have one. ## Agent-only and human-only content

Agents read the generated Markdown, so you can tune it separately from the page. Wrap content in `wc-if` with `for="agents"` and it appears only in the `.md` files, `llms-full.txt` and everything built from them, such as MCP results. Content with `for="humans"` appears only on the web page. The condition is evaluated at build time, so nothing is hidden with CSS.

```markdown
<wc-if for="agents">

The API base URL is `https://api.example.com/v2`. Send the key in the `Authorization` header.

</wc-if>
```

See [Conditional content](../components/conditional-content) for the other conditions.

## DocsLit Cloud

Sites on [DocsLit Cloud](../deployment/docslit-cloud) get all of this without setup, plus two extras.

**Hosted MCP endpoint.** Each site serves an MCP server over HTTP. It is stateless Streamable HTTP with JSON responses and no authentication:

```text
POST https://{slug}.{base-domain}/mcp
POST https://{host}/sites/{slug}/mcp
GET  https://{slug}.{base-domain}/.well-known/mcp.json
```

`/.well-known/mcp.json` describes the endpoint, the transport, the supported protocol versions and the tools, unless your site publishes its own file at that path. The server offers `list_pages`, `get_page`, `search_docs` and `get_docs_overview`. It negotiates protocol versions 2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05, accepts batches of up to 20 messages, and sets open CORS headers. A `GET` returns 405, except a browser navigation that asks for HTML, which falls through to your site's own `/mcp` page.

Here the hosted `get_page` takes a `page` argument, which accepts an id, a path or a full URL. The local reader tool takes `slug` instead.

**Markdown negotiation.** The server returns Markdown when `Accept` lists `text/markdown` with a higher quality value than `text/html`, or lists it first on a tie. A bare `*/*` never counts, so browsers and plain `curl` keep getting HTML. Responses carry `Vary: Accept`, an `ETag` and `X-Content-Type-Options: nosniff`. A request for `/` returns `index.md` or `llms.txt`.
