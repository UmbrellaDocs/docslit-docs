# Validation

The `docslit validate` command checks your project for common errors — broken links, missing pages, unknown components, and incomplete frontmatter.

## Run validation

```bash
docslit validate
```

The output shows errors, warnings, and informational messages with colored indicators. Autogenerated sidebars are expanded before the checks run.

`validate` finds broken things. It does not judge quality. For that, run [`docslit lint`](lint).

Line numbers count from the first line of the file, including the frontmatter, so they match what your editor shows.

## What gets checked

| Check | Level | Description |
|---|---|---|
| Config file exists | Error | docslit.json must exist and parse as valid JSON |
| Sidebar structure | Error | The sidebar array must exist in the config |
| Page files exist | Error | Every slug in the sidebar must have a matching .md file in docs/ |
| Internal links | Error | Links to other pages must point to valid page slugs |
| Asset references | Error | Images whose path starts with `/`, `./` or `../` must exist. `wc-image` and `wc-download` paths are not checked |
| Code imports | Error | `file=` imports must find the file, region and line range. See [Import code from files](../writing-content/code-import) |
| Page titles | Warning | Every page should have a title in its frontmatter |
| Component tags | Warning | All wc-* tags must be built-in or defined in components/ |
| Duplicate slugs | Warning | Each page slug should appear only once in the sidebar |
| Orphaned pages | Info | Markdown files in docs/ that are not listed in the sidebar. Pages with `sidebar: false` are skipped |
| Includes and variables | Error or warning | `wc-include` targets, `wc-var` names and undefined `{{NAME}}` placeholders |
| Frontmatter keys | Info | Keys that are not in the [frontmatter schema](../writing-content/frontmatter) |
| OpenAPI | Error or warning | Spec and overlay files exist, `wc-endpoint ref` values exist, and every operation is documented |
| Theme preset | Error | theme must reference a valid built-in preset or a readable theme JSON file |
| Theme file | Error | Brand theme JSON must parse and use valid variable keys |

## Strict mode

By default, `validate` exits with code 0 if there are only warnings. Use `--strict` to treat warnings as errors:

```bash
docslit validate --strict
```

This is useful in CI pipelines where you want to enforce documentation quality:

```yaml filename=".github/workflows/validate.yml"
- run: npm install -g docslit
- name: Validate docs
  run: docslit validate --strict --external --format github
```

## External links

```bash
docslit validate --external
```

Checks `http(s)` links with HEAD (falls back to GET), 8s timeout, limited concurrency.

## GitHub Actions annotations

```bash
docslit validate --format github
```

Prints `::error file=…,line=…::message` so failures show inline on pull requests.

## JSON output

```bash
docslit validate --format json
```

Prints one JSON document and nothing else, for AI agents and scripts:

```json
{
  "ok": false,
  "summary": { "errors": 1, "warnings": 0, "infos": 0, "pages": 3 },
  "issues": [
    {
      "level": "error",
      "code": "sidebar-missing-file",
      "message": "Sidebar slug \"missing-page\" has no matching file (looked for docs/missing-page.md)",
      "file": "docslit.json",
      "fix": "Create docs/missing-page.md or remove \"missing-page\" from the sidebar"
    }
  ]
}
```

Each issue has a stable `code`, a `message`, a `file`, a `line` when it has one, and a `fix` when the validator knows one. The full list of codes is in [Machine-readable CLI](../ai-and-agents/machine-readable-cli#issue-codes).

## Custom components and validation

The validator scans your `components/` directory for `customElements.define` calls. Any `<wc-*>` tag that matches a custom component definition is treated as valid. Tags that are neither built-in nor custom trigger a warning.

<wc-callout type="tip" title="Run validation before deploying">
Add `docslit validate --strict` to your CI pipeline to catch broken links and missing pages before they reach production.
</wc-callout>
