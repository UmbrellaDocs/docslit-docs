# Component mapping

This page lists how `docslit import` converts Mintlify and Fern components. The tables are generated by running real conversions through the importer, the same code that backs `docslit import` and the [`convert_mdx` tool](migrate-with-ai#convert-one-page-with-convert_mdx), so the right-hand column is what you actually get. Attributes the importer cannot carry over are dropped and listed in the [migration report](import-reference#the-migration-report).

## Rules for every conversion

- **Spacing.** Every block component is written with its opening tag on its own line, a blank line, the body, a blank line and the closing tag. Without the blank lines, Markdown would swallow the closing tag.
- **Attributes.** They are kebab-case and double-quoted. A JSX boolean becomes a bare attribute when true and is omitted when false. An array such as `{["a", "b"]}` becomes a comma-separated string.
- **Icons.** `icon`, `iconType` and Fern icon strings pass through to `icon` and `icon-type`. DocsLit resolves Lucide and Font Awesome names, classes, emoji and image paths at build time. See [Icons](../components/icons).
- **`className`** is dropped, because Tailwind classes have no DocsLit equivalent. The report notes it once per file.
- **Titles.** Inline Markdown such as `**bold**` and `` `code` `` works in the `title`, `label` and `description` of accordions, cards, tiles, steps, tabs, tooltips and updates.
- **Snippets** move to `docs/_reusables/`. Props are filled into `{{prop}}` placeholders.
- **Mintlify variables.** Global `{{productName}}` variables become `attributes` with `UPPER_SNAKE` names, such as `{{PRODUCT_NAME}}`.
- **Unknown components** are kept in the page inside a warning callout titled "Unconverted component", and listed as an error in the report.
- **Mintlify tags in Fern files.** Fern accepts several Mintlify components, such as `Danger`, `Expandable`, `Columns`, `Panel`, `View` and `Visibility`. The importer handles them in both.

## Not converted to a component

Some Mintlify and Fern features have no DocsLit component. The importer replaces or drops them and says so in the report:

| Source | What happens |
|---|---|
| `Panel` right-rail content in Mintlify | Becomes a floating `wc-aside`. There is no table of contents replacement, so the report asks you to check placement. |
| `RunnableEndpoint`, `Schema`, `EndpointRequestSnippet`, `EndpointResponseSnippet`, `WebhookPayloadSnippet` in Fern | Replaced by a callout that points to the generated API reference, plus a warning. |
| `RequestExample` and `ResponseExample` pinned to a side column | Become inline code groups in the page. Mintlify's sticky column has no equivalent. |
| `Update` `rss` in Mintlify | Dropped. DocsLit generates feeds from pages whose id starts with `changelog/` or `blog/`. |
| `Visibility` for signed-in users or groups, and Fern `If` for roles or logged-in users | The block is removed, because a static site has no login. Content for signed-out readers is kept. |
| Fern `Tooltip` on code, and `CodeBlock` `links` | Dropped. The code is rendered as plain code. |
| Mintlify `Mermaid` props `actions` and `placement` | Dropped. DocsLit always shows the expand control. |
| `img` `actions` and `actionsPlacement`, table pagination | Dropped with a note. |
| `<MDX>` wrappers, `export const` values and conditional JSX | Wrappers are unwrapped and known literal values are inlined. Computed conditions are reported. |
| Twoslash, Shiki `[!code word:]`, and custom TextMate grammars in code blocks | Not supported. The block renders as plain highlighted code. |
